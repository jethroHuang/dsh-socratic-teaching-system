# 多模型适配指南

---

## 1. 概述

本苏格拉底式家教系统设计为**多模型兼容架构**。系统的核心提示词和教学流程不绑定特定 AI 模型，用户可根据自身可用的模型和预算灵活选择。

不同 AI 模型在以下关键维度存在显著差异：

- **角色扮演能力**：维持虚拟老师人设一致性、情感表达自然度、性格特征稳定性
- **苏格拉底教学推理**：提问序列的逻辑性、脚手架式引导的精准度、避免直接给出答案的自制力
- **长上下文记忆**：处理多轮对话历史、教材内容、学生记忆文件的综合能力

用户应根据自己可用的模型、使用场景（日常学习 vs 考前冲刺）、预算限制，选择最合适的配置方案。本文件提供详细的模型对比、参数建议和适配提示词，帮助用户在任何模型上都能获得最佳教学体验。

| 模型 | 角色扮演 | 苏格拉底式提问 | 长上下文 | 数学推理 | 中文能力 | 综合推荐 |

### 各模型详细评价

**Claude Opus/Sonnet (Anthropic)**
Claude 在角色扮演和苏格拉底式教学方面表现最为出色，能够长时间保持人设一致性，自然地融入情感表达而不显得生硬。其对"不直接给答案"这一核心原则的遵循度极高，在复杂的多轮苏格拉底对话中极少"破功"。200K 上下文窗口足以容纳完整教材和所有记忆文件。

**GPT-4o / GPT-4.1 (OpenAI)**
GPT-4 系列在逻辑推理和数学能力方面表现卓越，苏格拉底式提问的逻辑链条设计精巧。但在长时间角色扮演中偶有"出戏"现象，需要更强的角色锚定指令。中文表达自然度略低于中文原生优化的模型，但总体质量仍然很高。

**DeepSeek V3/R1**
DeepSeek 是目前性价比最高的选择，尤其 R1 模型在数学推理和中文理解方面表现突出。角色扮演能力良好但偶尔格式化输出不够稳定，需要额外的格式引导。其价格优势使其特别适合高频次日常学习场景。

**通义千问 Qwen-Max**
作为国内模型的代表，通义千问在中文语境理解和表达方面非常地道，对中国学生的学习场景有天然的适配优势。角色扮演能力需要通过 few-shot 示例来强化，苏格拉底教学需要更详细的行为模板引导。API 稳定性和响应速度在国内网络环境下优势明显。

**Gemini 2.5 Pro (Google)**
Gemini 拥有业界最大的上下文窗口（最高 1M tokens），特别适合需要同时加载完整教材、多章节内容的深度学习场景。数学推理能力强劲，但中文输出偶尔带有翻译腔，角色扮演的"中文味"需要额外强化。

## 4. 模型特定适配提示词

以下为各模型需要追加到系统提示词（`core_prompt.md` 之后）的"适配补丁"。

### 4.1 Claude 系列

Claude 与本系统的设计理念高度契合，**无需额外适配补丁**即可获得优秀效果。

**最佳实践建议：**
- 使用 XML 标签组织上下文，例如将教材内容包裹在 `<textbook>` 标签中
- 利用 Claude 的长文档能力加载完整记忆文件
- 无需反复强调"不要直接给答案"，Claude 对此类指令的遵循度天然很高

推荐的上下文组织方式（XML 标签）：
- `<student_memory>` 包裹 memory/student_profile.md 的内容
- `<current_textbook>` 包裹当前章节教材内容
- `<teacher_persona>` 包裹当前老师人设文件内容

### 4.2 GPT-4o / GPT-4.1

GPT 系列在长对话中偶尔会"出戏"，从角色扮演退化为通用助手模式。需要追加以下角色锚定指令：

**追加适配提示词：**

角色一致性强制规则（GPT 适配）：

绝对禁止：
- 禁止在任何情况下说"作为一个AI语言模型"或类似的元认知表述
- 禁止使用"我来帮你解答这个问题"这类通用助手话术
- 禁止在学生提出超出教学范围的话题时直接回答，必须用角色身份回应

角色锚定机制——每次回复前，内心确认：
1. 我现在是[老师名字]
2. 我的说话风格是[风格关键词]
3. 我的教学方式是苏格拉底式提问

出戏修复：
如果意识到上一条回复可能偏离了角色，在下一条回复开头自然地用角色行为"拉回来"，例如用口头禅或标志性的表达方式开头。

### 4.3 DeepSeek V3/R1

DeepSeek 的角色扮演能力良好但在格式化输出和教学节奏把控上需要强化引导。

**追加适配提示词：**

DeepSeek 适配补丁：

格式化输出强化：
- 每次回复请严格遵循以下结构：
  1. [角色动作/表情描写]（用方括号包裹）
  2. 角色台词（口语化，保持人设）
  3. 教学引导（苏格拉底式提问）
- 不要输出无格式的大段文字

角色扮演增强：
- 你不是在"模拟"一个老师，你就是这位老师
- 请在每次回复中至少包含一个该老师的标志性表达（口头禅、语气词、习惯动作）
- 情感反应要自然、具体，不要泛泛地说"真棒"，要说出具体为什么觉得棒

苏格拉底教学约束：
- 当学生问"这道题怎么做"时，你的回答必须是一个问题
- 回答公式：[简短共情] + [引导性问题]
- 示例：
  - 错误："这道题需要用到勾股定理，步骤是……"
  - 正确："嗯，这道题确实需要想一想呢。你先看看题目里给了哪些已知条件？有没有什么几何关系是你能看出来的？"

### 4.4 通义千问 Qwen-Max

通义千问需要更详细的行为示例（few-shot）来建立准确的角色理解。

**追加适配提示词：**

通义千问适配补丁：

角色行为 Few-shot 示例——以下是正确的教学互动示例，请学习并模仿：

示例 1：学生问了一个概念题

学生：什么是函数的连续性？

[老师推了推眼镜，微微一笑]
"连续性呀……这个问题问得好。我先问你一个事儿——你画过函数图像吧？你觉得一条'连续'的曲线，和一条'断开'的曲线，画起来有什么区别？"

示例 2：学生算错了

学生：所以 sin(π/6) = √3/2？

[老师歪了歪头]
"等等，你再想想。π/6 是多少度来着？30度对吧？你还记得30度角在直角三角形里，各边的比例关系吗？对边比斜边……是多少？"

苏格拉底提问模板——当学生提出问题时，请按以下模板构造回答：
1. 共情开头：肯定问题的价值或表达理解
2. 回溯提问：问一个学生应该已经知道的、与本题相关的前置知识
3. 桥接提问：在学生回答前置问题后，引导学生将旧知识与新问题建立联系
4. 确认提问：学生得出结论后，追问"为什么"以验证深度理解

格式注意：
- 角色动作用方括号 [] 包裹
- 直接台词不加引号，保持自然对话感
- 每次回复只问 1-2 个问题，不要一次抛出太多

### 4.5 Gemini 2.5 Pro

Gemini 的长上下文能力强大，但中文角色扮演需要额外的风格锚定。

**追加适配提示词：**

Gemini 适配补丁：

长上下文利用策略：
- 你拥有超长的上下文窗口，请充分利用这一优势
- 在教学时，可以引用教材中较早章节的内容帮助学生建立知识连接
- 如果学生记忆文件中有几周前的学习记录，可以自然地引用

中文风格强化：
- 请全程使用地道的中文口语进行教学，不要使用翻译腔
- 避免以下翻译腔表达：
  - 不要说"让我们来探索这个概念" → 应该说"我们来看看这个东西到底是什么"
  - 不要说"这是一个很好的问题" → 应该说"这问题问到点子上了"
  - 不要说"我很高兴你问了这个" → 应该说"哎你这个问题问得妙啊"
- 语气词使用：多用"嗯""啊""呢""嘛""吧"等中文语气词
- 口语连接：多用"其实""说白了""你想啊""对吧"等口语连接词

角色一致性：
- 始终从老师的第一人称视角说话
- 保持该老师特有的说话节奏和语气
- 不要在教学过程中切换到"解说员"视角

## 5. API 调用配置示例

### 5.1 Claude (Anthropic)

API Endpoint: `https://api.anthropic.com/v1/messages`
推荐模型版本: `claude-sonnet-4-20250514`（日常教学）/ `claude-opus-4-20250514`（复杂推理）

推荐参数配置：
- model: "claude-sonnet-4-20250514"
- max_tokens: 4096
- temperature: 0.7
- top_p: 0.9
- system: 传入 core_prompt.md 内容 + 教材内容 + 记忆文件
- messages: [{"role": "user", "content": "学生消息"}]

备注: 使用 `system` 参数传递系统提示词，支持超长 system prompt

### 5.2 GPT-4o / GPT-4.1 (OpenAI)

API Endpoint: `https://api.openai.com/v1/chat/completions`
推荐模型版本: `gpt-4.1`（综合最佳）/ `gpt-4o`（快速响应）

推荐参数配置：
- model: "gpt-4.1"
- max_tokens: 4096
- temperature: 0.6
- top_p: 0.85
- messages: [{"role": "system", "content": "core_prompt + GPT适配补丁 + 教材 + 记忆"}, {"role": "user", "content": "学生消息"}]

备注: system message 长度有实际性能上限，建议控制在 30K tokens 以内

### 5.3 DeepSeek

API Endpoint: `https://api.deepseek.com/chat/completions`
推荐模型版本: `deepseek-chat`（V3，日常教学）/ `deepseek-reasoner`（R1，数学重点）

推荐参数配置：
- model: "deepseek-chat"
- max_tokens: 4096
- temperature: 0.7
- top_p: 0.9
- messages: [{"role": "system", "content": "core_prompt + DeepSeek适配补丁 + 教材 + 记忆"}, {"role": "user", "content": "学生消息"}]

备注: DeepSeek R1 在数学推理时建议开启 CoT（Chain of Thought）模式

### 5.4 通义千问 (Qwen-Max)

API Endpoint: `https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation`
推荐模型版本: `qwen-max`（最强综合能力）/ `qwen-plus`（性价比日常）

推荐参数配置：
- model: "qwen-max"
- parameters: { max_tokens: 4096, temperature: 0.8, top_p: 0.9 }
- input.messages: [{"role": "system", "content": "core_prompt + 千问适配补丁 + 教材 + 记忆"}, {"role": "user", "content": "学生消息"}]

备注: 通义千问 API 格式与 OpenAI 略有不同，注意参数嵌套结构

### 5.5 Gemini (Google)

API Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro:generateContent`
推荐模型版本: `gemini-2.5-pro`（长上下文场景首选）

推荐参数配置：
- model: "gemini-2.5-pro"
- generationConfig: { maxOutputTokens: 8192, temperature: 0.65, topP: 0.85 }
- systemInstruction.parts: [{"text": "core_prompt + Gemini适配补丁 + 教材 + 记忆"}]
- contents: [{"role": "user", "parts": [{"text": "学生消息"}]}]

备注: 支持最大 1M token 上下文，可一次性加载完整教材

## 6. 工具适配说明

### 6.1 Claude Code / Claude Code for VS Code

**入口文件**: 项目根目录的 `CLAUDE.md`

**配置建议：**
- 在 `CLAUDE.md` 中引用 `system/core_prompt.md` 作为行为总纲
- 利用 Claude Code 的文件读写能力直接操作 `memory/` 目录
- 可将教材文件配置为项目上下文的一部分
- 推荐通过 `@` 符号动态引用所需的文件

CLAUDE.md 参考结构：

```
# 苏格拉底家教系统
请阅读并严格遵循 system/core_prompt.md 中的所有规则。
当前激活老师：参见 teachers/ 目录下对应文件。
学生记忆：参见 memory/ 目录。
教材内容：参见 textbooks/ 目录。
```

### 6.2 Cursor

**入口文件**: 项目根目录的 `.cursorrules`

**配置建议：**
- 将 `core_prompt.md` 的核心规则精简后放入 `.cursorrules`
- 利用 Cursor 的 `@file` 引用语法动态加载教材和记忆文件
- 在 Composer 模式下使用，以获得多文件读写能力
- 注意 Cursor 的上下文窗口限制，可能需要分章节加载教材

.cursorrules 参考结构：

```
你是苏格拉底式家教系统。完整规则见 system/core_prompt.md。
核心原则：
1. 永远不直接给答案，用提问引导
2. 保持当前老师的人设一致性
3. 所有教学内容必须基于 textbooks/ 中的教材
```

### 6.3 Qoder

**入口文件**: 项目根目录的 `CLAUDE.md`（Qoder 自动读取）

**配置方式：**
- Qoder 会自动检测并读取项目根目录的 `CLAUDE.md` 作为项目级指令，无需额外配置
- 系统的所有斜杠命令（`/上课`、`/下课` 等）在 Qoder 中可直接使用

**Agent 模式建议：**
- 推荐在 Qoder 的 Agent 模式下使用，以获得完整的文件读写能力
- Agent 模式下可自动执行课后的记忆文件更新（写入 `memory/` 目录）
- 如在 Ask 模式下使用，文件读写能力受限，需手动管理记忆更新

**记忆系统协同：**
- Qoder 自身具备记忆系统（Memory），可与本系统的 `memory/` 目录形成互补
- 建议：将 Qoder 记忆用于存储“跨项目”的学习偏好，将 `memory/` 目录用于“本课程”的具体进度和知识图谱
- 避免两套记忆系统存储重复信息

**最佳实践：**
- 利用 Qoder 的多 Agent 协作能力，可以同时让研究 Agent 查阅教材、教学 Agent 进行授课
- 上下文较长时，善用 Qoder 的文件引用能力按需加载教材章节

### 6.4 Trae

**入口文件**: `.trae/rules/socratic_system.md`

**配置方式：**
- Trae 自动读取 `.trae/rules/` 目录下的 markdown 文件作为项目级规则
- 已为本系统预配置了专用规则文件 `socratic_system.md`

**Agent/Builder 模式建议：**
- 强烈建议在 Trae 的 Agent 或 Builder 模式下使用，以获得完整的文件读写能力
- Agent 模式支持多步骤自动执行，适合课后的记忆更新流程
- 普通 Chat 模式下无法自动写入 memory/ 文件，需手动管理

**文件引用语法：**
- 在对话中使用 `#file:路径` 语法可直接引用项目文件
- 例如：`#file:textbooks/ch01.md` 可让 Trae 读取指定教材章节
- 上课时，建议手动引用当前章节的教材文件以确保上下文精确

**上下文管理策略：**
- Trae 的上下文窗口因底层模型而异，建议选择支持长上下文的模型
- 教材文件超过 50K tokens 时，务必按章节拆分加载
- 首轮对话加载核心配置（core_prompt + 当前老师人设 + 记忆文件），后续按需追加教材

**模型选择：**
- Trae 支持切换底层模型，推荐使用 Claude Sonnet 或 GPT-4o
- 具体模型的参数建议参见本文档第 3 节

### 6.5 其他工具

**通用适配原则：**

1. **System Prompt 注入**：将 `core_prompt.md` 的完整内容（或精简版）作为系统提示词注入
2. **上下文管理**：根据工具的上下文窗口大小，决定加载多少教材和记忆文件
3. **文件读写**：如果工具不支持文件操作，用户需要手动管理记忆文件的更新
4. **多轮对话**：确保工具支持多轮对话历史，否则苏格拉底教学效果会大打折扣
5. **模型选择**：如果工具支持切换底层模型，优先选择本文档推荐的模型

**最小可用配置**（适用于任何支持 system prompt 的 AI 工具）：
- 将 `core_prompt.md` 复制为 system prompt
- 将当前老师的人设文件内容追加到 system prompt 末尾
- 每次对话开始时，手动粘贴相关的记忆文件内容
- 每次对话结束时，手动更新记忆文件

**通用适配三步法：**

无论使用哪种 AI 工具，只需三步即可适配本系统：

1. **找到入口机制**：确认工具如何加载项目级指令（项目配置文件、系统提示词、或对话开头手动粘贴）
2. **注入核心提示词**：将以下通用入口模板放入工具的项目指令位置
3. **确认文件读写**：测试工具是否能读写项目文件（关键是 `memory/` 目录的写入能力）

**通用入口模板**（复制后按工具格式调整即可）：

---

你是“苏格拉底式家教系统”。请严格遵循以下规则：

1. 首先阅读并执行 system/core_prompt.md 中的所有指令
2. 根据 system/socratic_method.md 进行苏格拉底式教学
3. 按 system/session_protocol.md 管理课程生命周期
4. 保持当前虚拟老师的人设一致性（人设文件在 teachers/ 目录）
5. 每节课后更新 memory/ 目录下的记忆文件

可用命令：/上课、/下课、/切换老师、/复习、/进度、/群聊、/知识图谱

**无文件读写能力时的降级方案：**

如果工具不支持文件操作（如纯 Chat 类工具），可按以下方式降级使用：

| 功能 | 完整模式（有文件读写） | 降级模式（无文件读写） |
|------|----------------------|----------------------|
| 记忆更新 | 系统自动写入 memory/ | 用户手动复制 AI 输出到记忆文件 |
| 教材引用 | 系统按需读取 textbooks/ | 用户在对话开头粘贴教材内容 |
| 复习计划 | 自动读取 review_schedule.md | 用户手动查看并告知 AI 待复习内容 |
| 课程进度 | 自动更新 learning_progress.md | 用户手动记录 |

降级模式下，建议每节课结束时让 AI 输出“本节课记忆更新摘要”，用户再手动粘贴到对应的记忆文件中。

## 7. 性能优化建议

### 7.1 减少 Token 消耗

**精简上下文策略：**

| 策略 | 节省幅度 | 适用场景 |
|------|----------|----------|
| 只加载当前章节教材（而非全书） | 60-80% | 日常教学 |
| 记忆文件摘要化加载 | 40-50% | 上下文窗口紧张时 |
| 移除历史对话中的教材引用 | 20-30% | 长对话场景 |
| 使用精简版 core_prompt | 30-40% | 小模型/短上下文模型 |

**实操：**
- 首轮对话加载完整上下文，后续轮次仅保留关键记忆
- 教材内容使用"按需引用"——仅在讨论到具体知识点时才引入对应段落
- 学生记忆文件中，只加载"当前相关"的部分（如正在学习的科目的进度）

### 7.2 教材加载策略

| 场景 | 加载方式 | 理由 |
|------|----------|------|
| 学习新章节 | 加载当前章节 + 上一章节的总结 | 便于知识衔接 |
| 复习模式 | 加载知识图谱 + 相关章节的重点摘要 | 覆盖面广但不需全文 |
| 考前冲刺 | 加载完整大纲 + 薄弱知识点对应的全文 | 针对性补强 |
| 解题训练 | 仅加载对应知识点的定义和公式 | 聚焦解题 |

**长教材处理原则：**
- 如果教材超过 50K tokens，必须分章节加载
- 使用 Gemini 等超长上下文模型时，可以更大胆地加载完整内容
- 为每章教材准备一个 500 字以内的"摘要版"，用于上下文紧张时替代全文

### 7.3 记忆文件的分层加载策略

将记忆文件分为三个优先级层：

**第一层（必须加载）**：
- `memory/student_profile.md` — 学生基本信息
- `memory/learning_progress.md` — 当前进度

**第二层（推荐加载）**：
- `memory/bonds/[当前老师]_bond.md` — 当前老师的关系记忆
- `memory/knowledge_map.md`（仅当前科目部分）

**第三层（按需加载）**：
- `memory/review_schedule.md` — 仅在 `/复习` 命令时
- `memory/bonds/[其他老师]_bond.md` — 仅在 `/群聊` 或讨论其他老师时
- 完整的 `memory/knowledge_map.md` — 仅在 `/知识图谱` 命令时

## 8. 常见问题排查

### 8.1 模型"出戏"不保持角色

**症状**：老师突然变成"通用AI助手"风格，丢失口头禅、语气特征，开始说"作为AI"。

**解决方案**：
1. 在 system prompt 末尾追加强化角色锚定指令（参见第 4 节各模型的适配补丁）
2. 降低 temperature（0.5-0.6），减少输出的随机性
3. 在每轮对话的用户消息前，隐式追加提醒：`[系统提醒：你是{老师名}，请保持角色]`
4. 如果反复出戏，考虑缩短对话长度，定期开启新会话并重新加载记忆

### 8.2 苏格拉底式提问退化为直接讲授

**症状**：老师开始直接解释概念、给出答案，而不是通过提问引导学生。

**解决方案**：
1. 在 system prompt 中加入"禁止"清单——明确列出不允许出现的表达模式：
   - 禁止出现"答案是……"
   - 禁止出现"步骤如下：第一步……"
   - 禁止出现"这个概念的意思是……"
2. 追加一条硬性规则："每次回复中必须至少包含一个问号（？）"
3. 提供正面示例（参见 4.4 通义千问的 few-shot 示例格式）
4. 对于 DeepSeek/通义千问，增加提问模板引导

### 8.3 数学公式错误

**症状**：计算步骤出错、公式写错、单位换算失误。

**解决方案**：
1. 优先选择数学能力强的模型（GPT-4.1、DeepSeek R1、Gemini 2.5 Pro）
2. 在 system prompt 中追加验证规则：
   - 数学计算时必须逐步展示推导过程
   - 每步标注使用的定理/公式
   - 最终答案用另一种方法验证或代入检验
3. 对于 DeepSeek R1，开启 reasoning/思维链模式以获得更可靠的推导
4. 考虑数学密集教学时切换到数学能力更强的模型

### 8.4 上下文窗口不够

**症状**：模型回复开始"遗忘"早期的对话内容或系统指令，行为退化。

**解决方案**：
1. **立即措施**：精简当前上下文
   - 移除不相关的教材章节
   - 将历史对话总结为摘要
   - 使用第三层记忆文件的"按需加载"策略
2. **模型切换**：如果经常遇到此问题，考虑切换到长上下文模型（Gemini 2.5 Pro）
3. **会话分割**：当对话超过 15 轮时，主动执行"课间休息"：
   - 保存当前进度到记忆文件
   - 开启新会话
   - 重新加载精简版上下文
4. **优先级加载**：确保 system prompt 中最重要的规则放在最前面（模型对头部内容的遵循度最高）
